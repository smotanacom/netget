# OCI client evidence

Required peers: unmodified crane0.22.1, Python3 and OpenSSL in PATH. Missing peers fail, never skip. No download/container/global daemon/config change is needed locally. Programme run_cargo.py guard/shared target only, native loopback exchanges with100 test threads. Official crane Linux release pin is maintained by the programme coordinator; tests assert the native daemon version.

The owned crane public registry serve daemon runs through execve with temporary HOME and DOCKER_CONFIG, no ambient credential selection. Seed tiny config and binary layer blobs plus two tags using real native upload APIs solely as independent test fixture setup. Client probes, tags/catalog, tag/digest manifest reads, blob reads, both HEAD roles, and404 errors contact the unchanged daemon. A separate independent SDK CLI reads the seeded manifest. These fixtures prove native interoperability; no response generator or proxy alters crane responses.

Existing NetGet server pair covers advertised static/script examples, typed manifest/blob/head digest semantics. A mocked model chooses a tags read against crane and uses common memory in its actual result followup. Independent crane SDK reads tags from a token-protected NetGet server: version_check=llm exposes the native Bearer challenge on the initial v2 probe, then SDK selects token-service credentials from its owned0600 DOCKER_CONFIG and retries with the issued bearer. An owned loopback HTTP router places the token endpoint on the same origin as the registry, matching unchanged crane0.22.1's realm trust restriction. Every v2 request/response, including Authorization and native401, is forwarded to/from NetGet; the router supplies only its controlled token endpoint, never a registry answer. No password/token CLI arguments or ambient helper/agent are used. This proves the existing server role with an independently implemented auth client, rather than claiming NetGet's explicit client automatically retries. Pinned SDK trust rule: https://github.com/google/go-containerregistry/blob/v0.22.1/pkg/v1/remote/transport/bearer.go .

An owned Python HTTP auth peer measures actual Basic authentication, scope/service query, token request count and registry Authorization presence without recording credential strings. NetGet client refuses an untrusted separate token origin before I/O, then explicitly trusts the origin, handles a native repository401, refuses wrong credentials, obtains aliases/expiry metadata, sends a later explicit pull, redacts reflected password/token values and observes expiry at the peer. Token issuance alone is not registry authorization; no replay/refresh is performed. This peer is a controlled protocol fixture, not a complete independent registry daemon. OpenSSL proves refusal of an untrusted HTTPS certificate only.

A separate anonymous token exchange verifies no Basic credential is sent and still requires a later explicit pull. Runtime token setting and clearing are checked against actual subsequent Authorization presence; neither reports authentication success by itself.

Owned raw HTTP peers bound all connection tasks with a JoinSet/parent abort. Tests cover public startup probes/local token clear, timeout parameters/origins, pending overlap/disconnect, removal of a pending request plus parked manual handler, actual peer-observed socket closure, whole startup/request deadline, advertised Content-Length and chunked4MiB/+1 limits, encoding/redirect refusal and recovery, exact event queue8/+1 overflow and four handler followups. No fixed multisecond sleeps or missing-tool skips.

Pure schema tests exercise exact action depth32/nodes65536/retained8MiB/+1, constructed10000-level owned refusal, JSON depth/node/string/container/key/body limits, raw manifest1MiB/+1, blob4MiB/+1/text64KiB/+1, header counts/aggregate/value limits, strict repository/tag/digest grammar, raw-byte digest mismatch, descriptors/media/embedded-data scope, unverified HEAD metadata, pagination cursor/order/count/route/fallback, challenge/trust/scope, token alias/expiry refusals, fixed-schema reflection redaction and deep redactor guard.
