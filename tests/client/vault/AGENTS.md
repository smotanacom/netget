# Vault client verification

Use the programme run_cargo.py guard and shared target. Client target filter is vault::. Native peer is HashiCorp's vault daemon and CLI (verified locally2.0.0), discovered through PATH and the existing real_server helper. Missing peers fail. Python3 runs a thin process wrapper; it does not emulate Vault.

The wrapper owns a temporary HOME and loopback development daemon, clears its environment, uses -dev-no-store-token and filters root-token/unseal output. The native child stays in RealServer's owned process group and death tie. CLI provisioning uses the test's root token only through an environment variable, passwords/policies through stdin, and bounded completion deadlines. It never touches the user's Vault daemon, token file, configuration or helpers. No global installation or container is needed.

schema_test verifies selected native routes, version/CAS envelopes, distinct read/write/list/metadata shapes, typed auth metadata and credential omission, MFA/wrapping/lease refusal, unavailable-version/RFC3339 validation, streaming collection/body limits and duplicate/trailing JSON refusal. Escaped diagnostics, overlapping password/token values, reflected free-form keys and preservation of fixed schema names with short credentials are checked explicitly.

session_test uses an explicitly owned HTTP mock with a JoinSet for connection drivers. It checks public probe/token semantics, all selected health status codes, validated credential replacement and local clear, failed/incomplete login without partial success, later reflected-password/token redaction in events/access logs, content type/encoding/schema/body/redirect refusals, whole head/body deadlines with recovery, pending overlap, disconnect/removal during manual dispatch and pending I/O, four bounded handler followups and fresh injection, endpoint/startup validation.

real_server_test supplies independent daemon/CLI evidence: userpass-issued credential actually authorizes KV create/update/read/list/metadata; two CAS versions and historical/latest reads; CLI readback and metadata agreement; conflict400 and missing404; advertised static/script/action examples; mocked model selection of real login/write/read with shared memory and redacted auth/status. A NetGet pair preserves programmable KV v2 answers and the existing login404 refusal; a refused attempt clears the old startup credential. No private protocol store is introduced.

Run existing server Vault tests as well: native CLI against programmable server, error/failure behavior and shared connection/body bounds. The server idle-bound test takes about120 seconds. Keep that actual verification; do not shorten it to improve results. Experimental remains honest about missing API, TLS/browser runtime, capture and conformance coverage.
